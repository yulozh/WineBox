# YuixServer 架构说明

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                        SwiftUI 视图层                        │
│  ContentView ──┬── FileTreeView（文件树）                    │
│                ├── CodeEditorView（编辑器，语法高亮）         │
│                ├── AIPanelView（AI 聊天/指令）                │
│                ├── ServiceStatusBar（服务/端口/局域网 IP）     │
│                └── SettingsView（配置）                       │
└──────────────────────────────┬──────────────────────────────┘
                               │ @EnvironmentObject
                     ┌─────────▼─────────┐
                     │   ProjectStore     │  全局状态中枢（@MainActor）
                     │ 项目/文件树/服务/配置 │
                     └───┬──────┬──────┬─┘
        ┌────────────────┘      │      └────────────────┐
        ▼                       ▼                       ▼
   AIService             GitService                 ArchiveService
 (URLSession,OpenAI兼容)  (GitHub REST API)          (ZIPFoundation)
        │                       │                       │
        └───────────────┬───────┴───────────────────────┘
                        ▼
                  KeychainStore
        （API Key / GitHub Token 安全存储）
```

## 2. 各层职责

- **视图层**：只负责渲染与交互，状态通过 `ProjectStore` 单向流动（SwiftUI 声明式）。
- **ProjectStore**：`@MainActor` 的 `ObservableObject`，承载项目元数据、文件树、服务列表、AI/Git 配置；负责目录读写与文件 CRUD。
- **服务层**：无 UI、纯逻辑，通过 `URLSession`/`FileManager`/`Security` 等系统框架实现；密钥读写统一走 `KeychainStore`。
- **运行时抽象**：`RuntimeProviding`（`ServiceRegistry.swift`）隔离「合规 WASM 版」与「侧载子进程版」，实现替换不影响上层。

## 3. 关键数据流

### 新建项目
`NewProjectSheet` → `ProjectStore.createProject` → 创建目录 + 写模板 + 分配空闲端口 + 持久化 `projects.json` → 刷新文件树 → 底部状态栏同步显示服务。

### AI 生成代码
`AIPanelView.send` → `AIService.chat`（POST `/chat/completions`）→ 返回文本 → `extractCodeBlock` 抽取 fenced 代码 → 用户点「写入项目」→ 追加到当前项目入口文件并刷新树。

### Git push（Git Data API 六步）
取分支引用 → 取 base tree → 逐个创建 blob → 创建新 tree → 创建 commit → 更新分支引用。全程不依赖本地 `git` 二进制。

## 4. 安全模型

| 资产 | 存储位置 | 说明 |
|---|---|---|
| AI API Key | Keychain | `ai.apiKey` |
| GitHub Token | Keychain | `github.token` |
| 项目元数据 | 沙盒 Documents | 仅名称/语言/端口，不含任何凭证 |
| 代码文件 | 沙盒 Documents/YuixServer | 用户数据，可通过文件 App 导出 |

凭证**永不**进入源码、日志或 UserDefaults。

## 5. 平台限制与扩展点

iOS 沙盒的三条硬约束与对应设计：

1. **禁止子进程** → Git 用 REST API、运行时用 WASM 或侧载。
2. **禁止任意端口监听** → 合规版用应用内 `WKWebView` 预览；侧载版可监听真实端口。
3. **禁止访问系统文件** → 根目录固定在沙盒 `Documents/YuixServer/`。

扩展点：实现 `RuntimeProviding` 加入 WASM 子模块（如 `wasm-vfs` + 一个 Node/Python 的 Wasm 运行时），即可在合规前提下提供更真实的「运行」体验；或使用个人开发者签名在 `RuntimeProviding` 里用 `Process` 实现真实监听。

## 6. 后续可优化方向

- 编辑器接入 Runestone/CodeMirror，提升大文件高亮与补全体验。
- Git 增加 diff、merge 冲突处理与 PR 创建。
- AI 接入流式输出（SSE）与上下文文件注入（把当前文件内容送入 system prompt）。
- 容器压缩支持 `.tar.gz`（可基于 libcompression 扩展）。
